# ANGI Web

An on-demand WPE WebKit application embedded in ANGI's native desktop. Open **Web** from **Apps** (Super+Space). Native selection menus and JavaScript alert/confirm/prompt dialogs are supported. File picking, download management, tabs and browser extensions are outside this initial host. The window uses the same tiling, floating, resizing, fullscreen and header-collapse controls as other apps. Ctrl+L selects the address; Ctrl+R reloads.

The pinned engine is WPE WebKit 2.54.2, using the stable WPEPlatform API directly. Cog and a separate Wayland compositor are not required. The DRM platform is available in the engine build, but the embedded app uses a custom offscreen view backed by WPE's headless EGL/GBM display. Taking over the entire DRM display would bypass the desktop window manager.

`host.c` owns WebKit lifecycle and sandboxed user data; `platform.c` owns display/view integration and frame delivery; `protocol.c` owns bounded local IPC and WPE input events; `dialogs.c` owns form menus, script dialogs and routing user-opened links into the same window; `storage.c` keeps page data, HTTP cache, font cache and shader cache off the small SD root. The GUI's `src/browser/` owns process lifetime, chrome, input translation and presentation. No web engine is loaded into the GUI process. Closing Web honors unsaved-page confirmation, allows a brief graceful shutdown, then kills a stuck process group; hiding/collapsing unmaps its view. Hidden sites may still run JavaScript/network activity according to WebKit's background policies.

The current software/VNC desktop requires CPU-readable frames. WPE renders offscreen and the host converts BGRA to opaque RGBA while copying the page viewport into a sealed-size memfd. This avoids a separate GUI-side conversion pass. One frame waits for acknowledgment, with at most one pending engine buffer. The GUI presents native page pixels at up to approximately 30 fps without stretching them to fractional window dimensions; geometry updates are coalesced to at most ten per second during continuous resizing. The viewport is capped at 4096×2160. This is not a zero-copy display path.

This build includes JavaScript, CSS, Canvas and WebGL, subject to the installed Mesa driver. Multimedia (video, audio, WebRTC), WebDriver, spellchecking and speech synthesis are disabled at build time to reduce dependencies. The host disables developer extras and removes inspector-server environment overrides. Web content runs as the signed-in user with WebKit's bubblewrap sandbox enabled. The host refuses root. Normal HTTPS certificate verification remains enabled; on the appliance, cookies and caches live in `/var/lib/agx-data/agx-web-users/<uid>` with mode 0700. The greeter prepares this private store before dropping privileges. Other development hosts use XDG directories. Shader cache defaults to a 64 MiB limit. There is no privileged JavaScript bridge or remote debugging listener.

WPE renders through Mesa on the Pi GPU. The current Slint software/VNC desktop requires a CPU frame copy into shared memory; this is not a zero-copy display path. Presentation is bounded to about 30 fps with one frame in flight, resizing is throttled to 100 ms, and hidden/collapsed views are unmapped. WebKit may still run page JavaScript or network activity while hidden. Closing the app tears down its helper and web processes. Audio/video, file pickers, downloads, tabs and extensions are outside this initial app's scope.

Open **Web** from Apps with **Super+Space**. It participates in the existing tiled/windowed desktop: drag its header, resize its edges, maximize/fullscreen it, or double-click the header to collapse and restore in windowed mode. **Ctrl+L** focuses the address; **Ctrl+R** reloads; **Alt+Left/Right** navigates history. The page viewport follows the content area instead of stretching a fixed-resolution image.

The host delegates EGL/DRM rendering to WPE's headless platform so it can share the existing desktop without a compositor. The current Slint software/VNC desktop needs CPU pixels: frames cross a bounded shared-memory bridge capped near 30 fps, with one frame in flight and one pending engine buffer. This is not a zero-copy GPU compositor. Closing Web ends its engine processes; hidden/collapsed views are unmapped, though page timers and network activity follow WebKit policy. The offline home makes no startup network requests. Multimedia, file pickers, downloads and browser tabs are outside this first version.

The appliance bubblewrap patch retains its existing safe-open fallback when the external toolchain lacks the `openat2` syscall definition, even with a recent target kernel. It does not disable sandboxing.

Build with `scripts/build-web.sh` (`WEBKIT_BUILD_JOBS=3` by default to bound build memory). It builds the engine, native dependencies and `.cache/agx-web/agx-web`. The engine runtime is much larger than the embedding host. `make deploy-web` builds the GUI and engine, installs the runtime on NVMe, and restarts the GUI to expose the launcher entry. Sign in again afterward. This leaves the running appliance’s small SD root intact. New full images use a 512 MiB root partition to include the selected browser package. Never replace `/lib`, `/lib64`, libc or the active loader when installing the runtime on a running appliance.

`tests/smoke.html` exercises viewport resizing, typing, pointer clicks, scrolling, Canvas and WebGL. It is a manual/integration fixture, not part of the start page.

For incremental development, rebuild the local-source host with Buildroot’s `agx-web-rebuild` target after changing its C sources. `AGX_WEB_HOST` overrides the embedding-host path for desktop integration tests.
