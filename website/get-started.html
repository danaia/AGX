Get started

From a blank card to a
live, extensible system.

Every step of the one-prompt install on a Raspberry Pi 5. A direct Ethernet link over USB-C carries the install and live updates, and Wi-Fi carries the web. No ISO, no installer.

One promptUSB-C EthernetWi-Fi for the webEarly development
00

What you need

Gather these before you start. You do not need a monitor, a keyboard or a Wi-Fi connection for the Pi.

  • A Raspberry Pi 5.
  • A USB-A to USB-C data cable. A charge-only cable will not work.
  • A microSD card you can erase. A 32 GB card has been tested.
  • A card reader connected to your computer.
  • An Arch Linux computer using NetworkManager, with internet access and a coding agent that can run terminal commands, such as Codex or Claude Code. This is the tested setup.
01

Plug everything in

Connect the Pi to your computer with the data cable, and put the microSD card in your computer's card reader. Use one ANGI Pi at a time and leave its card slot empty for now.

YOUR COMPUTER
    │
    ├── USB-A ── data cable ── USB-C on the Raspberry Pi 5
    │
    └── Card reader ── microSD card to install ANGI onto

Everything on the selected card will be erased.

Disconnect other removable drives to make the card easier to identify.

02

Give your agent the prompt

Open your coding agent on your computer and paste the entire prompt. It fetches ANGI from GitHub, installs the build tools, builds the image with your SSH key, writes the card and sets up the USB-C Ethernet link.

The install prompt
Install ANGI OS on my Raspberry Pi 5 over USB-C. Do the whole install from this one prompt.

Setup
- The Pi is connected to this computer with a USB-A to USB-C data cable.
- The microSD card to erase and flash is in this computer's card reader.
- Source: https://github.com/danaia/ANGI.git

Rules
- Do the terminal work yourself and keep explanations short.
- Ask me only for what you cannot determine: passwords, approvals, or a physical action.
- Never write to a system disk or any drive I have not approved. Show me the card you identified and recheck it right before writing.

Steps
1. Inspect this computer: OS, disk space, memory, network manager and attached storage. Use the tested Arch Linux + NetworkManager workflow. If mine differs, tell me what is needed before changing anything.
2. Clone the repository from GitHub, or reuse an existing checkout without overwriting local changes. Read README.md and docs/phase1.md and follow them.
3. Reuse or create an Ed25519 SSH key without overwriting any existing key. Pass its public key as SSH_PUBLIC_KEY to every build command.
4. Install the build tools, then run make configure, make dependencies, make build and make check-image. Continue only when output/images/sdcard.img passes validation.
5. Create or reuse the agx-direct NetworkManager profile for the USB-C Ethernet link: MAC 02:77:00:00:00:01, 10.77.0.1/24 on this computer, no gateway, IPv6 off. Leave my internet connection untouched. The Pi will be 10.77.0.2.
6. Flash sdcard.img to the card I approved, verify the written bytes against the image, then eject it. I authorize erasing that card once you have shown it to me.
7. Ask me to move the card into the Pi and reconnect the cable. Wait for my go-ahead.
8. Connect as root@10.77.0.2, check the board identity and run agx status --json.
9. Open agx tui and explain its keys. Then offer to set up the Pi's Wi-Fi from the Network tab so the Pi can reach the web. The cable carries the install and live updates; Wi-Fi carries the internet.

Report what you verified and anything still unresolved.

Your agent may need your computer password or approval to install packages and write the card. Enter passwords through your computer's secure prompt. The first build downloads toolchains and sources, so allow time and stay online.

03

What your agent does

You can read along. This is what the prompt asks for, in order.

  • Inspects your computer: OS, disk space, memory, network manager and attached storage.
  • Clones the repository and reads the build docs, without overwriting local changes.
  • Reuses or creates an Ed25519 SSH key. The private key never leaves your computer.
  • Builds the image with make configure, make dependencies, make build and make check-image, and continues only when output/images/sdcard.img passes validation.
  • Prepares the USB link: an agx-direct NetworkManager profile that leaves your normal internet connection alone.
  • Writes the card. It shows you which card it identified, rechecks it right before writing, flushes, verifies the written bytes against the image, then ejects it.

One raw image, not an installer

The card receives a single disk image. There is no ISO to boot, no installer to click through and no setup wizard. The same image is what the Pi runs.

04

Move the card when asked

This is the only physical step. Once your agent says the card is written and verified:

  • Unplug the Pi's USB cable so it is powered off.
  • Take the microSD card out of your computer's reader and put it into the Pi's microSD slot.
  • Reconnect the USB cable.
  • Tell your agent: “The card is in and the Pi is connected. Continue.”
Before:  Computer ── card reader ── microSD
                                      │
                                move the card
                                      ↓
After:   Computer ── USB cable ── Pi [microSD]
05

Connect over the cable

Your computer and the Pi talk over a direct Ethernet link. It carries the install and every live update, and it needs no router. Your agent handles this step; these are the settings it uses.

USB-C Ethernet

Pi at 10.77.0.2

The Pi appears as an Ethernet device on the USB-C cable. Your computer uses 10.77.0.1/24 with no gateway. This is the install path.

RJ45 Ethernet

Pi at 10.78.0.2

A direct RJ45 cable between the two computers, with yours at 10.78.0.1/24 and the Pi on eth0. Also no router.

Wi-Fi

The web

The cable has no gateway, so it does not share your internet. The Pi reaches the web over Wi-Fi, which you set up from its dashboard.

One-time network profile on your computer (USB-C)
nmcli connection add type ethernet ifname '*' con-name agx-direct \
  802-3-ethernet.mac-address 02:77:00:00:00:01 \
  ipv4.method manual ipv4.addresses 10.77.0.1/24 ipv4.never-default yes \
  ipv6.method disabled connection.autoconnect yes
Check the link and sign in
nmcli device status
ping -c 3 10.77.0.2
ssh -i ~/.ssh/id_ed25519 root@10.77.0.2
agx status --json

The first connection asks you to trust the Pi's new host key. Reflashing produces new host keys, so check the fingerprint before removing an old entry with ssh-keygen -R 10.77.0.2.

06

Use ANGI

Your agent opens the terminal dashboard with agx tui, or gives you the exact command to open it yourself.

1Profile2Overview3Hardware4Network5System6Services7Logs
?HelpF9Power offF10RebootqBack to the Pi's terminal

Open the Network tab (4) to connect the Pi to Wi-Fi so it can reach the web. Click tabs and rows, or use the arrow keys and mouse wheel. To finish, ask your agent to shut the Pi down, or run poweroff, then wait a few seconds after the connection closes before unplugging.

07

Extend it, live

From here, nothing needs a reflash. Build and install new software through the same cable. Run agent angi on the Pi to describe something to build, or change the code on your computer and deploy it.

Deploy from your computer, over the Ethernet link
make deploy-tui      # terminal dashboard
make deploy-gui      # desktop
make deploy-init     # init and service supervisor
make deploy-network  # network services
  • Live refresh. An installed desktop release loads into the running session. It saves settings, then re-executes in the same process, so there is no reboot.
  • Rollback guard. A watchdog checks that the new release comes up and stays up, and restores the previous release if it does not.
  • Set AGX_SSH_HOST and AGX_SSH_KEY to point the deploy scripts at the USB-C (10.77.0.2) or RJ45 (10.78.0.2) address of your Pi.
The deploy targets need the build packages from the desktop section of the defconfig; see the project docs.
If you get stuck

Tell your agent what happened.

Ask it to keep diagnosing the setup. These are the usual causes.

The Pi keeps restarting or disconnecting

Your computer's USB port may provide too little power. Use a suitable powered data connection, or the official Pi power supply with an RJ45 Ethernet cable.

The agent cannot identify the card

Give it the card's capacity and reader details, and let it inspect devices again after you remove and reinsert the card.

The build stopped

Ask the agent to fix the error and resume. It reuses downloaded files and completed build work.

The dashboard looks wrong

Ask the agent to try agx tui --ascii --no-color --no-mouse.
