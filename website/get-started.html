Pi 4 / 400 setup over SSH

Tested from an erased card on a Raspberry Pi 4 Model B, including Wi-Fi reconnection after reboot and an HTTPS page in ANGI Web.

  1. 1

    Build and verify the card

    Your agent builds sdcard.img with your SSH public key and checks its SHA-256. It identifies the card and waits for your exact erase approval. It then writes, verifies every byte, and ejects the card.

  2. 2

    Boot and connect over USB-C

    Move the card into the powered-off Pi, connect a USB-C data cable to your computer, and power it on. Paste the second prompt in a new chat. Your agent checks the new SSH fingerprint before connecting. Use direct Ethernet and the Pi’s power supply if you need the fallback.

  3. 3

    Create the administrator and join Wi-Fi

    In the ANGI terminal dashboard, use Profile (1) to create your account, then Network (4) to set the country, scan, and connect. Type passwords in the terminal. The direct cable stays available if Wi-Fi needs another try.

  4. 4

    Open the desktop over VNC

    Your agent verifies Wi-Fi and opens an SSH tunnel. Connect a VNC viewer for your operating system to the local tunnel port and sign in with your new administrator account. Open ANGI Web to test an HTTPS page.

Get the Pi 4 install prompt
01

What you need

Gather these before you start. You do not need a monitor or a keyboard for the Pi, but ANGI must join Wi-Fi, so have your network details ready.

You need an AI agent that can run commands

The install runs inside a chat with a coding agent on your computer. Any agent harness or IDE works: Codex, Claude Code (terminal or VS Code), Cursor (agent mode), OpenCode, Hermes, or any other that can run terminal commands. Open it on the computer you are installing from, then paste the prompt into its chat. A chat in a browser tab, such as ChatGPT or claude.ai, cannot do it: it cannot run commands, build ANGI or write your card.

  • An AI agent that can run commands, open on your computer. Any harness or IDE works: Codex, Claude Code, Cursor, OpenCode, Hermes and others.
  • Your Raspberry Pi (Zero 2 W, 4, 400 or 5), or an ARM or Intel/AMD computer. See step 00.
  • A USB data cable that fits your computer and the Pi, or an Ethernet cable and a power supply if your Pi has an Ethernet port.
  • A microSD card you can erase. A 32 GB card has been tested.
  • A card reader connected to your computer.
  • A computer with internet access. The build and card-writing tools run on Linux. On Windows or macOS, use a Linux environment with direct access to the card reader, or prepare the card on a separate Linux computer. Use your host’s network settings, SSH client, and VNC viewer for setup.
  • Your Wi-Fi network name, password and two-letter country code. ANGI joins Wi-Fi during setup.
02

Put the card in your computer

Put the SD card in a card reader on your computer. The Pi stays off with an empty card slot and is not connected yet. If the card is in the Pi now, take it out: the Pi cannot format its own card.

YOUR COMPUTER
    │
    └── Card reader ── SD card   (formatted here, by your agent)

THE PI: off, card slot empty, not connected yet

Everything on the selected card will be erased

Your agent shows the card’s device path, size, model, serial and contents. It waits for you to type the erase confirmation with the exact device path.

03

The prompt: build ANGI and put it on the card

Open your coding agent on your computer and paste the entire prompt. It asks which computer ANGI is for and builds the image with your SSH key. The build takes about 1 to 3 hours: your agent tells you that up front, stays with it, checks its progress every few minutes and waits until it has finished. Then it shows you the card, waits for you to confirm the erase, and formats and writes the card and checks every byte. It ends by telling you exactly what to do with the card, and gives you the second prompt.

The prompt
INSTALL ANGI: build it and put it on an SD card, on this computer. I will tell you which computer ANGI is for.
Explain each step in one short, plain sentence. Do the terminal work yourself and
guide me through it: before each step say what you are about to do and what I will
see, tell me exactly when I need to do something physical, and wait for me. Ask me
only for passwords, approvals, or something physical. Write the built sdcard.img
straight onto my SD card or USB drive.

THE PLAN (tell me this in your first message, in plain words)
  1) You check this computer and build ANGI. This is the long part: about 1 to 3 hours
     for a first build, depending on this computer's CPU and internet speed. Give me
     your own estimate once you have checked this computer.
  2) You stay with the build the whole time, keep checking its progress, and tell me
     how it is going. I can leave it running.
  3) When the build has finished, you write it to my SD card or USB drive (I confirm the erase).
  4) Then you tell me exactly what to do with the SD card or USB drive and the target, and you give me
     a SECOND prompt to paste into a new chat. That second prompt is only given to me
     once the build and the SD card or USB drive are both finished. I do not have it yet.

Repository: https://github.com/danaia/ANGI.git

STEP 0 - ASK WHAT ANGI IS GOING ON
If I have not already said, ask me this and wait for the answer:
  1) Raspberry Pi Zero 2 W        (rpizero2w)
  2) Raspberry Pi 4 or 400        (rpi4)
  3) Raspberry Pi 5               (rpi5)
  4) ARM desktop or laptop        (arm-desktop)
  5) Intel/AMD desktop or laptop  (x86-desktop)
  6) Not sure - help me tell
If I answer 6, run scripts/detect-board.py --list and --host and show me the "how to
tell" lines (for a Pi, ask me to read the name printed on the board). Then run
scripts/detect-board.py --require BOARD and follow what it reports. If it says a
target has no image yet or has not been tried on hardware, tell me plainly and
continue only if I agree. Never write another target's image to my drive, and never
wipe this computer's disks or any disk I did not choose.

STEP 1 - CHECK THIS COMPUTER
Check the host operating system, free disk space (need 20 GB), memory, and that
my microSD card (or SD card or USB drive) is attached to THIS computer, in a card reader. The repository build and card writer use Linux. On macOS or Windows,
use a Linux environment that can access the physical card reader, or a separate
Linux computer. Confirm that access before proceeding. Check the build dependencies
and use the Linux distribution's package manager to install missing tools with approval.
Use the host's network settings for the direct link in part 2.

STEP 2 - GET AND BUILD ANGI
Clone the repository (or reuse a checkout without overwriting my changes). Use
~/.ssh/id_ed25519.pub as SSH_PUBLIC_KEY, or create an Ed25519 key without
overwriting any key. As my normal user run make configure, make dependencies,
make build and make check-image, each with BOARD=<my board>. Fix errors and
resume. Go on only when the image passes the check. For BOARD=rpi4, also verify
sdcard.img.sha256 in the selected build's images directory.

WATCH THE BUILD. THIS IS REQUIRED.
- Before you start make build, say: "The build takes a long time, about <your
  estimate>. I will keep watching it and checking its progress until it is finished."
- Run the build so you can watch it (in the background, writing to a log file), and
  look at the log every few minutes. Do not start it and walk away, and do not wait
  silently.
- Each time you check, tell me in one or two short lines: which stage it is on, whether
  it is still moving, and about how much time is left.
- If it stops, errors or looks stuck, tell me, find the cause and fix it, and resume.
- Do not assume it worked. Wait until the build has actually finished and
  make check-image has passed, then tell me clearly: "The build is complete." Do not
  start step 3 before that.

STEP 3 - ERASE AND FORMAT THE CARD ON THIS COMPUTER (needs my OK)
The SD card or USB drive must be attached to THIS computer. Never ask me to put it in the target
computer for this step. If it is not attached here, stop and ask me to attach it.
1. Run scripts/flash-sd.sh --list and show me the SD card or USB drive: path, size, model,
   serial, and what is on it. If there are several or I might not recognize it,
   ask me which. Never use a disk that holds this computer's system.
2. Say clearly that EVERYTHING on it will be erased. Wait for me to type the
   approval in the form "erase DEVICE", using the exact whole-device path reported
   by the Linux card writer. Anything else means no.
3. Then run scripts/flash-sd.sh --board BOARD --image IMAGE --device PATH --confirm-erase PATH.
   IMAGE is the sdcard.img from the build that passed the check.
   It wipes the old partitions, writes the image, checks every byte, and ejects.
   Wait for the command to finish successfully before saying the SD card or USB drive is ready.
   If it refuses, verification fails, or ejection fails, tell me. Do not try
   another disk. If a retry succeeds, tell me which attempt succeeded and have
   me close any terminal still showing the earlier failure.

STEP 4 - TELL ME WHAT TO DO NEXT, THEN GIVE ME THE SECOND PROMPT
Tell me the SD card or USB drive is ready and what happened ("built, written, every byte checked").
Then give me these steps as a short numbered list, one physical action per line:
  1) Power off the target (a desktop: shut it down).
  2) Take the finished card out of the card reader on this computer.
  3) Put it in the target: push a microSD card into the Pi's slot, gold contacts toward the board, until it seats. A desktop: plug the drive in.
  4) Connect it to this computer by Ethernet or USB-C data cable (desktops: no cable), then power it on.
  5) Wait up to 2 minutes for the first start. A Pi shows a red light, then a blinking green one.
Remind me to have my Wi-Fi network name, its password and my two-letter country
code ready, because the second part joins ANGI to Wi-Fi, which is the most important
step.
Right after the list, print the SECOND PROMPT for me: read the file docs/install-prompts/part2-BOARD.txt
from the checkout (BOARD is my board), and show its full text exactly as it is, in one
code block I can copy. Tell me to open a NEW chat with my agent and paste it there. Say
clearly that the first part is finished. Do not run the second part yourself and do not
continue past this step.

Your agent may need your computer password or approval to install packages and write the card. Enter passwords through your computer's secure prompt. The first build downloads toolchains and sources and takes about 1 to 3 hours, so allow time and stay online. You can leave it running; your agent reports progress.

04

What the prompt does

You can read along. This is what it asks for, in order.

  • Inspects your computer: OS, disk space, memory, network manager and attached storage.
  • Clones the repository and reads the build docs, without overwriting local changes.
  • Reuses or creates an Ed25519 SSH key. The private key never leaves your computer.
  • Builds the image with make configure, make dependencies, make build and make check-image. For Pi 4, it also verifies the checksum of output-rpi4/images/sdcard.img.
  • Formats the card, after you confirm. It lists the card with scripts/flash-sd.sh --list and waits for you to reply with its exact path. Then it rechecks the card, wipes the old partition table, writes the image, verifies every byte and ejects it.
05

Move the card, then connect

When the build is done and the card is written, your agent tells you what to do. This is the only physical step, and the first time the card goes into the Pi.

  • Power off the Pi.
  • Take the card out of your computer's reader and put it into the Pi's card slot.
  • Connect the Pi to your computer with an Ethernet cable or a USB-C data cable (Pi Zero 2 W: USB-C only). On a desktop, plug the drive in and start from it.
  • Power the Pi on, then open a new chat and paste the second prompt your agent gives you.
Before:  Computer ── card reader ── SD card
After:   Computer ── Ethernet or USB-C ── Pi [SD card]
06

The second prompt: get the system ready

Paste the second prompt into a new chat after the card is ready. It guides you through a trusted SSH connection, account setup, and Wi-Fi. On Pi 4, create your account in the terminal dashboard before joining Wi-Fi.

Have your Wi-Fi details ready

Bring your Wi-Fi network name, password, and two-letter country code. Enter the password in the terminal when prompted. The agent checks that ANGI can reach the web. A Pi Zero 2 W needs a 2.4 GHz network.

The connection settings your agent uses

On Windows, macOS, or Linux, configure the dedicated network adapter in your host’s network settings. Use the address below for that adapter, leave its gateway blank, and keep your existing internet connection in place.

USB-C Ethernet

Pi at 10.77.0.2

When the Pi appears as an Ethernet adapter over USB, give that adapter on your computer the address 10.77.0.1/24.

RJ45 Ethernet

Pi at 10.78.0.2

Connect a direct Ethernet cable and set your computer’s dedicated port to 10.78.0.1/24. Power the Pi from its own supply.

Wi-Fi

The web

The cable has no gateway, so it does not share your internet. The Pi reaches the web over Wi-Fi, which you set up from its dashboard.

Linux example using NetworkManager
nmcli connection add type ethernet ifname '*' con-name agx-direct \
  802-3-ethernet.mac-address 02:77:00:00:00:01 \
  ipv4.method manual ipv4.addresses 10.77.0.1/24 ipv4.never-default yes \
  ipv6.method disabled connection.autoconnect yes

Use your SSH client to connect to the Pi’s address with the key used to build the card. Check the host fingerprint before trusting it. If an existing fingerprint changes unexpectedly, verify the device’s identity before reconnecting.

Open the Network tab (4) to connect the Pi to Wi-Fi so it can reach the web. Click tabs and rows, or use the arrow keys and mouse wheel. To finish, ask your agent to shut the Pi down, or run poweroff, then wait a few seconds after the connection closes before unplugging.

08

Extend it, live

From here, nothing needs a reflash. Build and install new software through the same cable. Run agent angi on the Pi to describe something to build, or change the code on your computer and deploy it.

Deploy from your computer, over the Ethernet link
make deploy-tui      # terminal dashboard
make deploy-gui      # desktop
make deploy-init     # init and service supervisor
make deploy-network  # network services
  • Live refresh. An installed desktop release loads into the running session. It saves settings, then re-executes in the same process, so there is no reboot.
  • Rollback guard. A watchdog checks that the new release comes up and stays up, and restores the previous release if it does not.
  • Set AGX_SSH_HOST and AGX_SSH_KEY to point the deploy scripts at the USB-C (10.77.0.2) or RJ45 (10.78.0.2) address of your Pi.
The deploy targets need the build packages from the desktop section of the defconfig; see the project docs.
If you get stuck

Tell your agent what happened.

Ask it to keep diagnosing the setup. These are the usual causes.

The Pi keeps restarting or disconnecting

Your computer's USB port may provide too little power. Use a suitable powered data connection, or the official Pi power supply with an RJ45 Ethernet cable.

The agent cannot identify the card

Give it the card's capacity and reader details, and let it inspect devices again after you remove and reinsert the card.

The build stopped

Ask the agent to fix the error and resume. It reuses downloaded files and completed build work.

The dashboard looks wrong

Ask the agent to try agx tui --ascii --no-color --no-mouse.
