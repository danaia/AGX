Differentiators

Everything a person needs. Nothing an agent has to fight.

Most operating systems are made for people and adapted for agents later. ANGI starts from the other end.

Tiny by design

About 93 MB of files. A 0.5 MB init. Boots to SSH in roughly 2.5 seconds, and idles at about 120 MB of RAM.

Not a distribution

No package manager, no release cycle, no legacy to stay compatible with. Assembled from source with Buildroot, so the image holds only what ANGI asks for.

Swarm generated

Coding agents wrote the system and keep rewriting it. Three cooperating agents plan, build and test, and the OS itself is in scope.

Rust, top to bottom

PID 1, the service supervisor, network and account services, the CLI, the terminal dashboard and the desktop. About 11,000 lines in one workspace.

Everything is scriptable

Status, services, logs, Wi-Fi, accounts and power each have an agx command with --json output. What an agent can do, you can do.

Fully inspectable

One repository holds boot to dashboard. An agent can read it, change it, rebuild it, flash it and verify the result.

A desktop that respects your hands

Hyprland-style tiling and Omarchy's keyboard-first chords: Super + arrows to move focus, Super + Q to close, Super + 1–5 for workspaces. Borrowed experience, not a borrowed base system.

A fraction of the cost

Lightweight, low-cost models, each given only the intelligence a task needs. Small hardware, small bills.

01 / THE BOARD

A credit-card-sized computer.

A Raspberry Pi 5 is the machine ANGI is made for. No workstation, no rack, no cloud account. One affordable board, a power cable, and a network cable.

02 / THE SYSTEM

The entire OS barely registers.

ANGI is about 93 MB of files, boots to SSH in about 2.5 seconds, and idles at roughly 120 MB of the Pi's 16 GB. Almost everything is left over for the work.

~120 MBidle RAM on a 16 GB board
03 / THE SWARM

The agents work on the board itself.

An orchestrator, a builder and a tester compile natively on the Pi, with source, tools and caches on NVMe. The machine that runs the system is the machine that builds it.

04 / THE OUTPUT

Enterprise-grade software, shipped from one Pi.

Everything the swarm produces leaves over the network, scriptable and verifiable. That is the claim ANGI exists to prove: serious software does not need serious hardware.

Independent

No distribution underneath.

ANGI is assembled from source. It runs the Linux kernel and a few small, well-known components, then owns everything above them, which is where agents do their work.

  • Linux kernel trimmed for the Pi 5, with the Pi's own firmware bootloader.
  • Tiny, proven parts: BusyBox, Dropbear, wpa_supplicant, Mesa.
  • Everything else is ANGI, in Rust, readable by an agent.

install-angi.prompt
Install ANGI OS on my Raspberry Pi 5 over USB-C. Do the whole install from this one prompt.

Setup
- The Pi is connected to this computer with a USB-A to USB-C data cable.
- The microSD card to erase and flash is in this computer's card reader.
- Source: https://github.com/danaia/ANGI.git

Rules
- Do the terminal work yourself and keep explanations short.
- Ask me only for what you cannot determine: passwords, approvals, or a physical action.
- Never write to a system disk or any drive I have not approved. Show me the card you identified and recheck it right before writing.

Steps
1. Inspect this computer: OS, disk space, memory, network manager and attached storage. Use the tested Arch Linux + NetworkManager workflow. If mine differs, tell me what is needed before changing anything.
2. Clone the repository from GitHub, or reuse an existing checkout without overwriting local changes. Read README.md and docs/phase1.md and follow them.
3. Reuse or create an Ed25519 SSH key without overwriting any existing key. Pass its public key as SSH_PUBLIC_KEY to every build command.
4. Install the build tools, then run make configure, make dependencies, make build and make check-image. Continue only when output/images/sdcard.img passes validation.
5. Create or reuse the agx-direct NetworkManager profile for the USB-C Ethernet link: MAC 02:77:00:00:00:01, 10.77.0.1/24 on this computer, no gateway, IPv6 off. Leave my internet connection untouched. The Pi will be 10.77.0.2.
6. Flash sdcard.img to the card I approved, verify the written bytes against the image, then eject it. I authorize erasing that card once you have shown it to me.
7. Ask me to move the card into the Pi and reconnect the cable. Wait for my go-ahead.
8. Connect as root@10.77.0.2, check the board identity and run agx status --json.
9. Open agx tui and explain its keys. Then offer to set up the Pi's Wi-Fi from the Network tab so the Pi can reach the web. The cable carries the install and live updates; Wi-Fi carries the internet.

Report what you verified and anything still unresolved.

01 / PLUG IN

A cable is the whole install.

A Raspberry Pi 5, a USB-C data cable, and a microSD card. The cable is a direct Ethernet link between two computers. It carries the install and every live update, with no router and no monitor.

02 / ONE PROMPT

Paste one prompt into your coding agent.

It fetches ANGI from GitHub, installs the build tools, builds the image with your SSH key and asks only for what it cannot decide itself.

03 / ONE IMAGE

No ISO. No installer. No wizard.

The agent writes a single raw image to the microSD card and verifies every byte. Move the card to the Pi. That is the only physical step in the whole process.

04 / CONNECT

The cable becomes the network.

The Pi appears on your computer as an Ethernet device over USB-C. That link carries the install and live updates. The Pi reaches the web over Wi-Fi, which you set up from its dashboard.

ssh root@10.77.0.2Ethernet over the USB-C cable
05 / EXTEND, LIVE

Change the OS while it runs.

Build and install new software through the same Ethernet link. A deploy loads the new release into the running desktop. It keeps the same process and needs no reboot, and a watchdog restores the previous release if the new one does not stay up.

make deploy-guino reflash, no reboot
